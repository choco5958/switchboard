# CLI마다 계정 여러 개

같은 CLI에 계정을 여러 개 등록하고, 한 계정이 사용량 한도에 걸리면 다음 계정으로 같은 대화를 이어 간다. 지금은 Claude Code만 외부 도구 ccr로 이렇게 할 수 있다. 이 일을 앱이 직접 하고, 다른 CLI에도 같은 방식을 적용한다. 2026-11-09에 정했다.

## 원칙

- 계정마다 그 CLI의 홈 폴더를 따로 두고, 실행할 때 홈 환경 변수로 가리킨다. 로그인 정보는 그 폴더에만 남는다.
- 기본 계정은 사람이 원래 쓰던 로그인이다. 앱은 그 폴더를 옮기거나 고치지 않는다.
- 대화 기록은 모든 계정이 같이 쓴다. 그래야 계정을 바꿔도 같은 대화를 이어 갈 수 있다. 추가 계정의 홈에서 기본 홈의 기록 폴더를 심볼릭 링크로 가리킨다.
- SQLite 파일은 링크하지 않는다. WAL 파일이 링크한 쪽 경로에 생겨서, 두 계정이 같은 데이터베이스를 서로 다른 WAL로 열게 된다.
- 설정 파일은 실행할 때마다 기본 홈에서 복사한다. 링크하면 CLI가 저장하면서 파일을 새로 만들 때 링크가 끊긴다.
- 앱은 토큰 파일을 읽지 않는다. 화면에 보이는 계정 이름은 토큰이 없는 파일에서 읽거나 사람이 붙인 이름을 쓴다.
- ccr가 설치되어 있으면 Claude는 지금처럼 ccr에 맡긴다.

## CLI별 방법

| CLI | 홈 환경 변수 | 로그인 | 같이 쓰는 기록 | 복사하는 설정 | 한도를 아는 방법 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `CLAUDE_CONFIG_DIR` | `claude auth login` | `projects`, `todos`, `file-history`, `plans`, `shell-snapshots`, `session-env`, `paste-cache`, `tasks`, `transcripts`, `agents`, `commands`, `skills`, `rules` | `settings.json`, `CLAUDE.md` | mod의 사용량 보고에서 창이 100% |
| Codex | `CODEX_HOME` | `codex login` | `sessions`, `archived_sessions`, `prompts`, `skills`, `rules` | `config.toml`, `AGENTS.md` | 연결 서버가 띄우는 app-server의 사용량 보고에서 창이 100% |
| Gemini | `GEMINI_CLI_HOME`(아래 `.gemini`) | 처음 실행할 때 "Sign in with Google" | `.gemini/tmp`, `.gemini/extensions` | `.gemini/settings.json`, `.gemini/GEMINI.md`, `.gemini/projects.json` | 화면 끝의 "exhausted your daily quota", "Usage limit reached for" |
| Qwen | `QWEN_HOME`(그 자체가 `.qwen`) | 처음 실행할 때 인증 선택(API 키) | `QWEN_RUNTIME_DIR`를 기본 홈으로 | 없음(설정에 계정의 키가 들어 있다) | 화면 끝의 "Quota exhausted: " |
| Copilot | `COPILOT_HOME` | `copilot login` | `session-state` | 없음(`config.json`에 로그인한 사용자가 들어 있다) | 없음 |

- Codex는 연결 서버에 `CODEX_HOME`을 넘기지 않는다(0.166에서 확인). 그래서 앱이 서버 인수 `--cli-home`으로 계정의 홈을 알려 주고, 서버는 그 홈으로 사용량을 읽는다.
- 폴더 신뢰(Codex, Copilot)와 Codex 훅 신뢰는 계정의 홈 설정에 적는다.
- Copilot의 한도 문구는 GitHub가 주는 모델에서만 나온다. 직접 붙인 모델로는 재현할 수 없어 확인하지 못했다. 그래서 Copilot은 계정을 여러 개 쓰고 대화를 이어 갈 수는 있지만, 한도에 걸려도 저절로 옮기지 않는다.

OpenCode와 Crush는 넣지 않는다. 둘 다 API 키로 제공자에 붙고, 대화 기록이 계정 정보와 같은 데이터베이스(OpenCode)나 프로젝트 폴더(Crush)에 있다. OpenCode는 `opencode auth switch`로 이미 키를 바꿀 수 있다.

## 동작

### 계정 등록

- 계정 목록은 `~/.claude-ide/accounts.json`, 홈은 `~/.claude-ide/accounts/<CLI>/<번호>/`에 둔다. 1번은 기본 계정이다.
- 설정의 에이전트 CLI 화면에 설치된 CLI마다 계정 목록을 보여 준다. "계정 추가"는 새 홈을 만들고 그 홈으로 로그인 명령을 독의 터미널에서 연다. 목록은 로그인을 스스로 알아챈다.
- "빼기"는 목록에서만 뺀다. 홈과 그 안의 로그인은 남기고, 다음에 추가하는 계정은 새 번호를 받는다.
- 새 세션은 로그인했고 한도에 걸리지 않은 첫 계정으로 연다(`src/main/accounts.ts` `runAccount`). 계정이 하나뿐이면 아무 환경 변수도 더하지 않아 전과 같다.
- ccr가 설치되어 있으면 Claude Code는 지금처럼 ccr에 맡긴다.

### 한도에 걸리면 다음 계정으로

`src/main/accountRotate.ts`가 15초마다 앱이 계정으로 연 세션을 본다.

1. 한도를 알면 그 계정에 풀리는 시각을 `~/.claude-ide/account-limits.json`에 적는다. 화면으로 안 한도는 한 시간으로 본다.
2. 같은 CLI에 한도에 걸리지 않은 계정이 없으면 아무것도 하지 않고 알림만 보낸다. 지금처럼 풀릴 때까지 기다린다(src/shared/limit.ts).
3. 있으면 그 터미널에 Ctrl-C를 CLI가 끝날 때까지 최대 네 번 보낸다. Gemini는 한도 창을 먼저 닫아야 해서 한 번 더 누른다. 끝나지 않으면 옮기지 않고 알린다.
4. 다음 계정으로 새 터미널을 열어 같은 대화를 잇는다. Claude Code는 세션 id로(`--resume`), 다른 CLI는 그 폴더의 마지막 대화로(`codex resume --last`, `gemini --resume latest`, `qwen --continue`) 연다.
5. 새 세션이 브리지에 나타나면 "하던 일을 이어서 해 주세요"를 보낸다.

## 확인

`scripts/account-check.ts`가 실제 CLI와 이 스크립트의 가짜 모델로 확인한다. CI의 Test 워크플로가 macOS, Linux, Windows에서 돌린다.

- 기본 계정에서 한 턴을 하고, 앱과 같은 방법으로 준비한 계정 2에서 그 대화를 이어 간다. 두 번째 요청에 첫 턴이 들어 있어야 통과한다. Claude Code, Codex, Gemini, Qwen, Copilot 모두 통과했다. 기록을 같이 쓰지 않게 하면(`ACCOUNT_CHECK_UNSHARED=1`) 실패하는 것도 확인했다.
- `--limit`(Gemini, Qwen): 가짜 모델이 모든 턴을 한도로 거절할 때 화면 끝에 앱이 찾는 문구가 나오고, 앱이 누르는 대로 Ctrl-C를 누르면 CLI가 끝난다.
- Codex가 연결 서버에 넘기는 환경 변수는 직접 확인했다(`HOME`, `LANG`, `LOGNAME`, `PATH`, `SHELL`, `TERM`, `TMPDIR`, `USER`).

확인하지 못한 것:

- 실제 유료 계정이 한도에 걸린 상황. Claude Code와 Codex는 기존 사용량 보고(창이 100%)를 그대로 쓴다.
- 로그인 명령 자체(`claude auth login`, `codex login`, `copilot login`). 실제 계정이 필요하다.
