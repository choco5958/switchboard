# CLI마다 계정 여러 개

같은 CLI에 계정을 여러 개 등록하고, 한 계정이 사용량 한도에 걸리면 다음 계정으로 같은 대화를 이어 간다. 2026-11-09 결정 당시에는 Claude Code만 외부 도구 ccr로 이렇게 할 수 있었다. 이 일을 앱이 직접 하고, 다른 CLI에도 같은 방식을 적용한다.

2026-11-16부터 공개 문서는 ccr를 안내하지 않는다. 앱은 이미 설정된 외부 계정 전환 도구를 알아보는 코드만 남아 있고(`src/main/termAccount.ts`), 이 문서는 설치나 사용법을 다루지 않는다.

## 원칙

- 계정마다 그 CLI의 홈 폴더를 따로 두고, 실행할 때 홈 환경 변수로 가리킨다. 로그인 정보는 그 폴더에만 남는다.
- 기본 계정은 사람이 원래 쓰던 로그인이다. 앱은 그 폴더를 옮기거나 고치지 않는다.
- 대화 기록은 모든 계정이 같이 쓴다. 그래야 계정을 바꿔도 같은 대화를 이어 갈 수 있다. 추가 계정의 홈에서 기본 홈의 기록 폴더를 심볼릭 링크로 가리킨다.
- SQLite 파일은 링크하지 않는다. WAL 파일이 링크한 쪽 경로에 생겨서, 두 계정이 같은 데이터베이스를 서로 다른 WAL로 열게 된다.
- 설정 파일은 실행할 때마다 기본 홈에서 복사한다. 링크하면 CLI가 저장하면서 파일을 새로 만들 때 링크가 끊긴다.
- 앱은 토큰 파일을 읽지 않는다. 화면에 보이는 계정 이름은 토큰이 없는 파일에서 읽거나 사람이 붙인 이름을 쓴다.
- 이미 설정된 외부 계정 전환 도구가 있으면 Claude는 그 도구에 맡긴다. 앱은 이 도구를 설치하거나 권하지 않는다.

## CLI별 방법

| CLI | 홈 환경 변수 | 로그인 | 같이 쓰는 기록 | 복사하는 설정 | 한도를 아는 방법 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `CLAUDE_CONFIG_DIR` | `claude auth login` | `projects`, `todos`, `file-history`, `plans`, `shell-snapshots`, `session-env`, `paste-cache`, `tasks`, `transcripts`, `agents`, `commands`, `skills`, `rules` | `settings.json`, `CLAUDE.md` | mod의 사용량 보고에서 창이 100% |
| Codex | `CODEX_HOME` | `codex login` | `sessions`, `archived_sessions`, `prompts`, `skills`, `rules` | `config.toml`, `AGENTS.md` | 연결 서버가 띄우는 app-server의 사용량 보고에서 창이 100% |
| Gemini | `GEMINI_CLI_HOME`(아래 `.gemini`) | 처음 실행할 때 "Sign in with Google" | `.gemini/tmp`, `.gemini/extensions` | `.gemini/settings.json`, `.gemini/GEMINI.md`, `.gemini/projects.json` | 화면 끝의 "exhausted your daily quota", "Usage limit reached for" |
| Qwen | `QWEN_HOME`(그 자체가 `.qwen`) | 처음 실행할 때 인증 선택(API 키) | `QWEN_RUNTIME_DIR`를 기본 홈으로 | 없음(설정에 계정의 키가 들어 있다) | 화면 끝의 "Quota exhausted: " |
| Copilot | `COPILOT_HOME` | `copilot login` | `session-state` | 없음(`config.json`에 로그인한 사용자가 들어 있다) | 없음 |

- Codex는 연결 서버에 `CODEX_HOME`을 넘기지 않는다(0.166에서 확인). 그래서 앱이 서버 인수 `--cli-home`으로 계정의 홈을 알려 주고, 서버는 그 홈으로 사용량을 읽는다.
- 폴더 신뢰(Codex, Copilot)와 Codex 훅 신뢰는 계정의 홈 설정에 적는다.
- Claude Code의 폴더 신뢰와 연결 서버 설정은 `.claude.json`에 로그인 정보와 함께 있어서 파일째 복사할 수 없다. 계정의 `.claude.json`이 있으면(로그인한 뒤) 실행할 때마다 기본 계정의 파일에서 프로젝트별 `hasTrustDialogAccepted`(참일 때만), `mcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`, `enableAllProjectMcpServers`와 맨 위의 `mcpServers`를 옮겨 적는다(`claudeStateText`). 같은 이름은 기본 계정 값을 따르고, 계정에만 있는 것은 남긴다. 신뢰가 없으면 계정을 옮긴 터미널에 "Quick safety check" 메뉴가 뜨고, 첫 선택이 "No, exit"라서 앱이 이어 하라고 보내는 Enter에 Claude가 끝난다(2.1.317에서 확인).
- Copilot의 한도 문구는 GitHub가 주는 모델에서만 나온다. 직접 붙인 모델로는 재현할 수 없어 확인하지 못했다. 그래서 Copilot은 계정을 여러 개 쓰고 대화를 이어 갈 수는 있지만, 한도에 걸려도 저절로 옮기지 않는다.

OpenCode와 Crush는 넣지 않는다. 둘 다 API 키로 제공자에 붙고, 대화 기록이 계정 정보와 같은 데이터베이스(OpenCode)나 프로젝트 폴더(Crush)에 있다. OpenCode는 `opencode auth switch`로 이미 키를 바꿀 수 있다.

## 동작

### 계정 등록

- 계정 목록은 `~/.claude-ide/accounts.json`, 홈은 `~/.claude-ide/accounts/<CLI>/<번호>/`에 둔다. 1번은 기본 계정이다.
- 설정 > 계정이 따로 있다(Orca의 계정 설정처럼). 설치된 CLI마다 묶음 하나, 계정마다 행 하나를 보여 준다. 행에는 이름(없으면 번호), 가린 이메일, 로그인 여부, 한도가 풀리는 시각, 그 계정의 열린 세션이 마지막으로 알린 사용량이 보인다.
- 행을 누르면 그 계정이 "사용 중"이 되고, 새 세션은 그 계정부터 시도한다(`accounts.json`의 `active`). 이미 열린 세션은 처음 연 계정을 그대로 쓴다.
- "계정 추가"는 새 홈을 만들고 그 홈으로 로그인 명령을 독의 터미널에서 연다. 목록은 로그인을 스스로 알아챈다. 행마다 이름 바꾸기, 다시 로그인, 빼기(확인 창을 거친다)가 있다.
- "빼기"는 목록에서만 뺀다. 홈과 그 안의 로그인은 남기고, 다음에 추가하는 계정은 새 번호를 받는다.
- 새 세션은 사용 중인 계정부터 번호 순으로, 로그인했고 한도에 걸리지 않은 첫 계정으로 연다(`src/main/accounts.ts` `runAccount`). 계정이 하나뿐이면 아무 환경 변수도 더하지 않아 전과 같다.
- 이미 설정된 외부 계정 전환 도구가 있으면 Claude Code는 그 도구에 맡긴다. 앱은 이 도구를 설치하거나 권하지 않는다.

### 한도에 걸리면 다음 계정으로

`src/main/accountRotate.ts`가 15초마다 앱이 계정으로 연 세션을 본다.

1. 한도를 알면 그 계정에 풀리는 시각을 `~/.claude-ide/account-limits.json`에 적는다. 화면으로 안 한도는 한 시간으로 본다.
2. 같은 CLI에 한도에 걸리지 않은 계정이 없으면 아무것도 하지 않고 알림만 보낸다. 지금처럼 풀릴 때까지 기다린다(src/shared/limit.ts).
3. 있으면 그 터미널에 Ctrl-C를 CLI가 끝날 때까지 최대 네 번 보낸다. Gemini는 한도 창을 먼저 닫아야 해서 한 번 더 누른다. 끝나지 않으면 옮기지 않고 알린다.
4. 다음 계정으로 새 터미널을 열어 같은 대화를 잇는다. Claude Code는 세션 id로(`--resume`), 다른 CLI는 그 폴더의 마지막 대화로(`codex resume --last`, `gemini --resume latest`, `qwen --continue`) 연다.
5. 새 세션이 브리지에 나타나면 "하던 일을 이어서 해 주세요"를 보낸다.

## 확인

`scripts/account-check.ts`가 실제 CLI와 이 스크립트의 가짜 모델로 확인한다. CI의 Test 워크플로가 macOS, Linux, Windows에서 돌린다.

- 기본 계정에서 한 턴을 하고, 앱과 같은 방법으로 준비한 계정 2에서 그 대화를 이어 간다. 두 번째 요청에 첫 턴이 들어 있어야 통과한다. Claude Code, Codex, Gemini, Qwen, Copilot 모두 통과했다. 기록을 같이 쓰지 않게 하면(`ACCOUNT_CHECK_UNSHARED=1`) 실패하는 것도 확인했다.
- `--limit`(Gemini, Qwen): 가짜 모델이 모든 턴을 한도로 거절할 때 화면 끝에 앱이 찾는 문구가 나오고, 앱이 누르는 대로 Ctrl-C를 누르면 CLI가 끝난다.
- Codex가 연결 서버에 넘기는 환경 변수는 직접 확인했다(`HOME`, `LANG`, `LOGNAME`, `PATH`, `SHELL`, `TERM`, `TMPDIR`, `USER`).

확인하지 못한 것:

- 실제 유료 계정이 한도에 걸린 상황. Claude Code와 Codex는 기존 사용량 보고(창이 100%)를 그대로 쓴다.
- 로그인 명령 자체(`claude auth login`, `codex login`, `copilot login`). 실제 계정이 필요하다.

## 2026-11-19 덧붙임: 같은 로그인으로 두 번 등록한 계정

- 브라우저가 이미 로그인된 상태에서 계정을 추가하면 새 계정이 기존 계정과 같은 로그인이 되기 쉽다. 두 행은 한도가 같아서, 한 행이 한도에 걸려 다음 행으로 옮겨도 곧바로 다시 멈춘다.
- 앱은 토큰이 없는 파일로 로그인을 비교한다. Claude Code는 `.claude.json`의 `oauthAccount`에 있는 계정 ID와 조직 ID를 보고(계정 ID가 없으면 이메일), Gemini는 `google_accounts.json`의 `active`를 본다. Codex, Qwen, Copilot은 그런 파일이 없어 비교하지 않는다. 비교한 값은 화면에 보이지 않고 어디에도 보내지 않는다.
- 같은 로그인인 행 가운데 뒤쪽 행에 `같은 로그인`을 표시한다. 한 행이 한도에 걸리면 같은 로그인인 행도 함께 한도로 기록해서, 같은 대화를 그 행으로 다시 열지 않는다.
- 같은 사람이 다른 조직의 좌석으로 로그인한 Claude Code 계정은 한도가 따로라서 다른 로그인으로 본다.
- 확인: 단위 테스트, 그리고 임시 홈에 가짜 파일을 두고 띄운 실제 앱의 설정 화면. 실제 로그인으로는 확인하지 못했다.

## 2026-11-25 덧붙임: Claude Code를 끝낸 뒤에 옮기고, 앱을 다시 켠 뒤에도 옮긴다

- 한도에 걸린 Claude Code 세션을 옮길 때 원래 터미널의 Claude Code가 끝나지 않은 채 같은 대화가 새 터미널에서 열렸다(macOS, Linux). 앱은 터미널 앞에 있는 프로그램의 이름으로 CLI가 도는지 보는데, Claude Code 터미널에는 견줄 이름이 없어서 늘 끝난 것으로 읽었다. Ctrl-C를 보내지 않았고, 끝났는지 기다리지도 않았다.
- 이름으로는 알 수 없다. macOS가 알려 주는 이름은 `claude` 링크가 가리키는 파일의 이름이라서, npm으로 설치한 2.1.327은 `claude.exe`이고 설치 프로그램으로 설치한 것은 버전 번호(`2.1.327`)다. 그래서 견줄 이름이 없는 터미널에서는 셸이 아닌 프로그램이 앞에 있으면 CLI가 도는 것으로 본다. 다른 CLI는 전처럼 이름으로 본다.
- 앱을 닫았다 열면(업데이트 포함) 터미널 호스트가 지켜 준 터미널의 세션은 더 옮기지 않았다. 어느 계정으로 열었는지를 앱이 메모리에만 두었기 때문이다. 이제 터미널 호스트가 보관하는 터미널 정보에 계정 번호를 함께 두고, 앱이 다시 붙을 때 CLI가 앞에 있는 터미널만 다시 살핀다. 셸이 앞에 있는 터미널은 이미 옮겼거나 CLI를 끝낸 터미널이라서 살피지 않는다. 같은 대화를 한 번 더 여는 일을 막으려는 것이다.
- 이전 버전의 터미널 호스트가 지키던 터미널에는 계정 번호가 없어서, 그 터미널은 전처럼 옮기지 않는다.
- 확인: 단위 테스트, 그리고 실제 터미널(node-pty)에 띄운 실제 Claude Code 2.1.327에 앱의 옮기기 함수를 돌려서, 고치기 전에는 Ctrl-C 0번에 `claude.exe`가 앞에 있는 채로 새 터미널을 열고, 고친 뒤에는 Ctrl-C 2번으로 끝난 다음에 여는 것을 봤다. 그 Claude Code는 로그인하지 않은 첫 화면이었다. 실제 계정이 한도에 걸린 화면에서 Ctrl-C로 끝나는지, 앱을 다시 켠 뒤의 옮기기를 실제 앱에서 하는 것은 확인하지 못했다.
