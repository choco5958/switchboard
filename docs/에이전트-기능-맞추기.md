# 에이전트 기능 맞추기 계획

Claude Code가 아닌 CLI에서도 Switchboard의 기능을 Claude Code와 같게 쓰게 한다. 2026-11-05에 정했다.

## 지금 상태와 이유

| 기능 | Claude Code | Codex, Gemini, Qwen, Copilot, OpenCode, Goose, Amp | Cursor, Grok, Kimi, Crush |
| --- | :---: | :---: | :---: |
| 작업 보고, 결정 질문, 세션끼리 묻기, 브라우저 도구 | ✅ | ✅ | 터미널만 |
| 답과 메시지 받기, 예약 프롬프트 | ✅ | ✅ | |
| 자리 비운 동안 권한 확인 중계 | ✅ | 없음 | |
| 사용량 막대, 사용량 한도에서 멈추기 | ✅ | 없음 | |
| `/switchboard` 패널 | ✅ | | |

- **터미널만인 네 CLI:** 앱은 사용자 설정(`~/.cursor` 등)을 고치지 않고, 실행 한 번에만 연결 서버를 붙인다(src/shared/agents.ts). 이 넷은 그렇게 붙일 플래그나 환경 변수를 문서에 두지 않았다.
- **권한 확인 중계:** Claude Code에서는 mod의 `tool.check` 훅이 권한 질문 직전에 끼어들어 브리지의 `/approvals`에 올리고 답을 기다린다(mod/hooks/register.ts, approval.ts). 다른 CLI에는 연결 서버만 붙는다. 연결 서버는 CLI가 부르는 도구라서, CLI가 띄우는 권한 질문을 보지 못하고 답하지도 못한다.
- **사용량:** mod가 Claude Code의 사용량(5시간, 7일)을 `/sessions/usage`로 보낸다. 다른 CLI의 사용량은 아무도 보내지 않는다. 그래서 막대도 비고, 한도에 닿은 세션에 프롬프트를 미루는 일(src/shared/limit.ts)도 Claude Code에만 된다.
- **패널:** Claude Code 화면 안에 그리는 mod 전용 화면이다. 같은 내용이 앱에 있다.

## 원칙

- 사용자 설정 파일을 고치지 않는다. 실행 한 번에만 쓰는 플래그, 환경 변수, 앱 폴더의 파일로 붙인다. 예외는 설정에서 사람이 켠 경우뿐이고, 기본은 꺼짐이다(지금의 폴더 신뢰 기록과 같다).
- 로그인을 끊는 방법은 쓰지 않는다.
- 세션 토큰은 지금처럼 연결 서버의 메모리에만 둔다. 파일에 적지 않는다.
- 문서에 없는 방법은 시험으로 확인한 뒤에만 쓴다. CLI가 바뀌어 안 되면 터미널만 여는 쪽으로 물러난다.
- 실제 CLI로 확인하지 못한 연결은 README와 릴리스 노트에 그렇다고 적는다.

## 설계

### 1. 권한 확인 중계

```
CLI의 권한 훅 ─ mcp/hook.ts (CLI가 실행) ─ 로컬 소켓 ─ 연결 서버(mcp/server.ts) ─ 브리지 /approvals ─ 앱, 휴대폰, Telegram
```

- **훅 명령 `mcp/hook.ts`:** CLI가 권한을 묻기 직전에 실행하는 짧은 명령이다. 표준 입력으로 CLI의 JSON을 받아 도구 이름과 실행할 내용으로 바꾸고, 같은 실행의 연결 서버에 묻는다. 받은 답을 그 CLI의 형식으로 표준 출력에 쓴다. CLI마다 다른 입출력은 `mcp/permission.ts`의 작은 변환 함수가 맡고, 각각 단위 테스트를 둔다.
- **연결 서버가 중개한다:** 연결 서버는 시작할 때 `~/.claude-ide/agents/<터미널 키>.sock`(Windows는 같은 이름의 named pipe)을 연다. 권한은 0600이다. 훅이 보낸 요청을 자기 토큰으로 `/approvals`에 올리고, mod처럼 긴 폴링으로 답을 기다린다(approval.ts의 `waitApproval`을 그대로 쓴다). 토큰은 연결 서버 밖으로 나가지 않는다.
- **같은 실행인지 확인:** 터미널 키(`SWITCHBOARD_TERMINAL`, 128비트 무작위 값)를 비밀값으로 쓴다. 연결 서버는 실행 인자로, 훅은 CLI가 넘긴 환경 변수로 받는다. 소켓 이름은 키의 해시이고, 소켓은 키가 맞는 요청만 받는다.
- **언제 묻나:** mod와 같다. 사람이 자리를 비웠고, 요약이 잘리지 않은 경우에만 휴대폰으로 보낸다. 그 밖에는 훅이 아무 결정도 하지 않아서 CLI가 평소처럼 터미널에서 묻는다. 연결 서버나 브리지가 응답하지 않을 때도 같다.
- **기다리는 시간:** mod는 6시간까지 기다린다. CLI 훅에는 시간 제한이 있으니, CLI마다 설정할 수 있는 최대값을 쓴다. 시간이 다 되면 답을 포기하고 터미널 질문으로 넘긴다(브리지에 `abandon`).
- **화면과 브리지는 바꾸지 않는다.** 권한 요청은 Claude Code의 것과 같은 결정 대기열에 같은 모양으로 들어간다.
- **`AgentPreset`에 `permissionHook` 항목을 더한다:** `mcp`처럼 훅 명령과 설정 파일 경로를 받아 플래그, 환경 변수, 파일을 돌려준다. 없으면 중계하지 않는다.

CLI별로 붙이는 방법(2026-11-05 조사, 0단계에서 확인):

| CLI | 훅 | 실행 한 번에만 켜기 | 판단 |
| --- | --- | --- | --- |
| Codex | `PermissionRequest` 훅, 허용과 거부 | `-c`로 `[hooks]`를 넣는 방법은 문서에 없음. 훅 신뢰도 필요 | 신뢰 처리 방법을 정한 뒤 붙인다(정할 것 1) |
| Qwen | `PermissionRequest` 훅, 허용과 거부 | `QWEN_CODE_SYSTEM_SETTINGS_PATH`로 앱 파일 지정 | 붙인다. 사용자의 시스템 설정을 가리지 않는지 확인 |
| Copilot | `permissionRequest` 훅, 허용과 거부(샌드박스 밖 실행은 허용 불가) | `--plugin-dir`의 플러그인. 플러그인 훅은 문서에 없음 | 0단계 시험 뒤 붙인다 |
| OpenCode | 플러그인의 `permission.asked` 이벤트, SDK로 답함 | `OPENCODE_CONFIG_DIR`(사용자 설정과 합쳐짐) | 붙인다. 훅 명령 대신 앱 폴더의 JS 플러그인이 소켓에 묻는다 |
| Gemini | 거부만 가능, 허용은 결국 터미널에서 다시 물음 | | 붙이지 않는다. 무료와 Pro 사용자는 Antigravity CLI로 옮겨 감 |
| Goose, Amp | 훅은 있음 | 사용자 설정 폴더에만 둘 수 있음 | 붙이지 않는다. README에 이유를 적는다 |

### 2. 터미널만인 CLI 연결

| CLI | 방법 | 판단 |
| --- | --- | --- |
| Crush | `-D <앱 폴더>`. 그 폴더의 `crush.json`이 사용자 설정 위에 합쳐지고, 로그인은 전역 데이터에 있어 그대로다(소스 internal/config/load.go) | 붙인다. 그 실행의 대화 기록이 앱 폴더에 쌓인다(정할 것 2) |
| Cursor | `--plugin-dir <앱 폴더>`의 플러그인에 `mcp.json`, `--approve-mcps` | 0단계 시험 뒤 붙인다 |
| Grok | `--plugin-dir`의 플러그인에 연결 서버 | 0단계 시험 뒤 붙인다. 플러그인이 기본으로 켜지는지 확인 |
| Kimi | 설정 폴더를 바꾸면 로그인이 끊긴다. 프로젝트 `.kimi-code/mcp.json`은 저장소에 파일을 남긴다 | 터미널만 연다. README에 이유를 적는다 |

- 플러그인 폴더는 `~/.claude-ide/agents/` 아래에 실행마다 만들고, 지금의 설정 파일처럼 오래된 것을 지운다(`pruneFiles`).

### 3. 사용량

- **Codex:** `codex app-server`의 `account/rateLimits/read`와 `account/rateLimits/updated` 알림이 사용률, 기간(분), 초기화 시각을 준다(문서에 있음).
  - Codex 세션의 연결 서버가 `codex app-server`를 하나 띄워 두고 알림을 받는다. 받은 값을 `/sessions/usage`의 `rateLimits`로 보낸다. 기간이 300분이면 `five_hour`, 10080분이면 `seven_day`로 맞춘다.
  - 그러면 사용량 막대와 한도에서 멈추기가 화면과 브리지를 바꾸지 않고 Codex에도 된다.
  - app-server는 사용자의 `~/.codex` 로그인을 읽기만 한다. 세션이 끝나면 함께 끝낸다.
- **Copilot, Gemini:** 다른 프로그램이 사용량을 읽는 방법이 문서에 없다. 막대는 비워 두고 README에 적는다.

### 4. 패널

만들지 않는다. 다른 CLI는 자기 화면에 다른 프로그램이 그릴 자리를 내주지 않고, 같은 내용이 앱에 있다.

### 5. README

- 표의 빈칸을 없애고 칸마다 "됨", "안 됨(이유)" 가운데 하나를 쓴다. 이유는 표 아래 짧은 목록으로 둔다.
- 실제 CLI로 확인하지 못한 연결은 "시험 전"으로 적는다.
- 네 언어 README를 함께 고친다.

## 정할 것

1. **Codex 훅 신뢰:** Codex는 신뢰를 기록한 훅만 실행한다.
   - `--dangerously-bypass-hook-trust`를 쓰면 기록 없이 돌지만, 그 실행의 다른 훅(클론한 저장소의 훅 포함)도 신뢰 없이 돈다. 쓰지 않는다.
   - 대신 설정 > 에이전트 CLI에 "Codex 권한 확인 중계"를 두고(기본 꺼짐), 켜면 앱이 Switchboard 훅 하나만 Codex 설정에 신뢰로 기록한다. 폴더 신뢰 기록(src/main/agentTrust.ts)과 같은 방식이다.
   - 이 방식이 Codex 0.166에서 되는지는 0단계에서 확인한다.
2. **Crush 대화 기록:** `-D`를 쓰면 그 실행의 대화 기록이 앱 폴더에 저장된다.
   - 프로젝트마다 고정된 앱 폴더(`~/.claude-ide/agents/crush/<프로젝트 해시>`)를 써서, 앱에서 다시 열면 이어지게 한다.
   - 앱 밖에서 `crush`로 열면 그 기록은 보이지 않는다. README에 적는다.
3. **실제 CLI 확인:** 이 Mac에는 Codex와 Goose만 설치되어 있다.
   - Crush, Cursor, Grok, Qwen, Copilot, OpenCode를 실제로 확인하려면 설치와 로그인이 필요하다. 로그인은 사람이 해야 한다.
   - 사람이 로그인하지 않은 CLI는 자동 테스트와 설정 파일 검사까지만 하고, README에 "시험 전"으로 적는다.

## 단계

0. [x] **시험 (Codex 0.166, 2026-11-05):**
   - `-c hooks.PermissionRequest=[...]`로 넣은 훅은 `/<session-flags>/config.toml:permission_request:0:0` 키로 읽힌다. 신뢰는 `config.toml`의 `hooks.state`에 해시로 기록되고, `codex app-server`의 `hooks/list`(해시와 신뢰 상태)와 `config/batchWrite`로 Codex가 직접 쓴다. 해시는 훅 정의 전체라서 명령이 같으면 실행마다 다시 기록할 필요가 없다.
   - `codex exec`는 권한을 묻지 않아 훅이 불리지 않는다. 앱 터미널의 Codex(TUI)와 `app-server`에서는 불린다.
   - 입력: `session_id`, `turn_id`, `cwd`, `hook_event_name`, `tool_name`(`Bash`, `apply_patch`, MCP 도구), `tool_input.command`, `tool_input.description`. 출력: `hookSpecificOutput.decision.behavior`가 `allow`나 `deny`(`message`). 아무것도 출력하지 않으면 Codex가 평소처럼 묻는다. 사용자의 다른 PermissionRequest 훅도 함께 돌고, 하나라도 거부하면 거부다.
   - 훅에 CLI의 환경 변수가 그대로 넘어와 `SWITCHBOARD_TERMINAL`을 읽을 수 있다.
   - `account/rateLimits/read`가 `primary`, `secondary` 창(`usedPercent`, `windowDurationMins`, `resetsAt` 초)을 준다.
   - `--dangerously-bypass-hook-trust`는 쓰지 않는다.
1. [x] **중계 뼈대:** `mcp/permission.ts`(소켓 경로, CLI별 변환), `mcp/hook.ts`(훅 명령), 연결 서버의 `listenForHooks`와 `approve`, `AgentPreset.permissionHook`. 시험 브리지로 허용, 거부, 터미널로 넘기기, 다른 키, 서버 없음, 자리에 있을 때를 테스트한다(mcp/permission.test.ts).
   - 소켓은 `~/.claude-ide/agents/h-<키 해시>.sock`이다. 경로가 약 104바이트를 넘는 긴 HOME에서는 중계하지 않는다.
   - Windows에서는 아직 붙이지 않는다(훅 명령의 셸과 named pipe를 확인하지 못했다).
2. [x] **Codex:** 설정 > 에이전트 CLI의 "Codex 권한 확인 중계"(기본 꺼짐)를 켜면 Codex 터미널을 열 때 `src/main/codexHook.ts`가 신뢰를 기록하고 훅을 붙인다. 신뢰 기록에 실패하면 훅 없이 연다. 명령(Bash)은 샌드박스 밖 실행이라 터미널에서만 묻고, 파일 수정과 MCP 도구만 중계한다. 사용량은 연결 서버가 `codex app-server`를 띄워 2분마다 읽고, 계정 패널에 Codex 막대로 보인다.
   - 실제 Codex로 확인: 파일을 만드는 `apply_patch` 질문이 시험 브리지의 결정 대기열에 들어오고, 허용하자 파일이 만들어졌다. 사용량은 세션에 `seven_day`로 들어왔다. 앱 화면에서 켜고 휴대폰으로 답하는 것은 아직 확인하지 않았다.
3. [ ] **Crush 연결**(정할 것 2).
4. [ ] **Qwen, OpenCode 권한 중계.**
5. [ ] **Cursor, Grok 연결과 Copilot 권한 중계:** 0단계에서 된다고 확인한 것만 붙인다.
6. [ ] **README와 설정 화면:** 표를 새로 쓰고, 설정 > 에이전트 CLI의 연결 방법 설명(`agents.how.*`)을 고친다. 네 언어를 함께 고친다.
