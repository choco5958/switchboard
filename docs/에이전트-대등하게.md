# 모든 에이전트를 대등하게

Switchboard가 Claude Code를 기준으로 삼지 않게 한다. 2026-11-06에 정했다. 두 가지를 함께 한다.

- **A. 연결의 깊이를 같게:** 에이전트마다 그 CLI의 훅과 플러그인으로 Claude Code의 mod와 같은 일을 하는 층을 만든다. 모두 같은 공통 규격을 따르고, Claude Code의 mod도 그 구현 가운데 하나가 된다.
- **B. 서로를 도구로 부르기:** 어느 에이전트에서든 다른 에이전트에게 일을 맡기고 결과를 받는다.

[에이전트-기능-맞추기.md](에이전트-기능-맞추기.md)의 다음 단계다. 그 문서가 권한 확인 중계와 연결을 맞췄고, 이 문서는 나머지 동작과 앱의 구조를 맞춘다.

## 지금 차이

mod는 Claude Code의 사건마다 끼어든다. 다른 CLI의 연결 서버는 도구만 내주고, CLI 안에서 일어나는 일을 보지 못한다.

| mod가 하는 일 | 다른 CLI에서 지금 |
| --- | --- |
| 답과 메시지를 프롬프트로 넣기 | 앱 터미널에 입력한다. 앱 밖에서는 `check_answers`로 가져간다 |
| 턴이 끝나면 마지막 답을 보낸 쪽에 돌려주기(`/messages/turn-end`) | 없다. 에이전트가 `send_to_session`으로 직접 답해야 한다. 예약 프롬프트는 6시간 뒤 "결과 없음"으로 실패한다 |
| 도구를 쓰는 동안 일하는 중이라고 알리기(`/sessions/activity`) | 없다. 멈춤 감지, 잠자기 막기가 동작하지 않는다 |
| 프롬프트에 남은 질문과 압축 뒤 복원 내용 붙이기 | 없다 |
| 권한 확인 중계 | Codex, Qwen, Copilot, OpenCode 2만(3단계에서 Crush 추가) |
| 사용량 보고 | Codex만 |
| 하위 에이전트 보고, 멈추기, 이어 가기, 대화 보기 | 없다 |
| `/switchboard` 패널 | 없다(만들지 않는다) |

Claude를 기준으로 한 곳:

- 브리지는 세션이 `agent`를 보내지 않으면 Claude로 본다. `autoReplies(id)`가 `agent === 'claude'`로 메시지 문구와 취소 명령을 가른다(bridge/server.ts).
- Claude Code는 프리셋 목록(`PRESETS`)에 없고 따로 띄운다(terminals.ts `openClaudeIn`).
- 사용량 막대는 Claude 세션만 모으고, Codex는 따로 그린다(TopBar.tsx). 지난 세션은 Claude 기록만 읽는다.
- 화면 문구 24곳이 Claude를 이름으로 부른다.

## 원칙

- 앱과 브리지는 에이전트의 **이름이 아니라 능력**을 보고 동작을 고른다. 세션이 등록할 때 할 수 있는 일(턴 끝 알림, 활동, 사용량, 권한 중계, 프롬프트 덧붙이기)을 함께 알린다.
- 지금처럼 사용자 설정 파일은 고치지 않는다. 실행 한 번에만 쓰는 훅, 플러그인, 환경 변수로 붙인다.
- 실제 CLI로 확인한 것만 켠다. 확인은 [scripts/relay-check.ts](../scripts/relay-check.ts)처럼 CI에서 세 OS로 돌릴 수 있게 만든다.
- CLI에 방법이 없으면 그 능력은 비워 두고, 화면은 빈 것을 "없음"으로 보여 준다.

## 설계

### A. 공통 연결 규격

```
CLI의 훅/플러그인 ─ mcp/hook.ts ─ 로컬 소켓 ─ 연결 서버(mcp/server.ts) ─ 브리지
Claude Code의 mod ──────────────────────────────────────────────── 브리지
```

- **사건 다섯 가지:** 권한 질문, 턴 시작, 턴 끝(마지막 답 포함), 도구 사용(활동), 프롬프트 제출(덧붙일 내용 받기). 지금 권한 질문만 다니는 훅 소켓으로 나머지 넷도 보낸다. `HookAdapter`를 사건별로 넓힌다(mcp/permission.ts).
- **연결 서버가 mod처럼 처리한다:** 턴 끝이면 `/messages/turn-end`, 도구 사용이면 `/sessions/activity`, 프롬프트 제출이면 남은 질문과 복원 내용을 돌려준다. mod의 순수 함수(batch.ts, tools.ts)를 그대로 쓴다.
- **브리지는 능력으로 가른다:** `autoReplies`를 세션이 알린 `turnEnd` 능력으로 바꾼다. 능력을 알리지 않은 세션은 지금과 같다.
- **Claude Code도 프리셋으로:** `PRESETS`에 넣고 `via: 'mod'`로 둔다. 띄우는 코드는 지금 것을 쓰되, 목록, 감지, 배지, 사용량은 다른 에이전트와 같은 길로 지나게 한다.
- **사용량:** 막대를 에이전트별 줄로 바꾼다. 읽을 방법이 있는 에이전트만 채운다.
- **문구:** "Claude"를 "세션"이나 "에이전트"로 바꾼다. Claude Code에만 있는 기능(ccr 슬롯, `--resume`)은 그대로 둔다.

CLI별로 붙일 수 있는 사건(0단계에서 실제 CLI로 확인):

| CLI | 확인할 것 |
| --- | --- |
| Codex | 훅의 UserPromptSubmit, Stop, PostToolUse(Codex 0.166). 지금 PermissionRequest와 같은 신뢰 기록으로 붙는지 |
| Qwen | 같은 이름의 훅을 시스템 기본 설정 파일로 |
| Copilot | 플러그인 훅의 userPromptSubmitted, postToolUse, 턴 끝 사건 |
| Cursor | 플러그인 훅(beforeSubmitPrompt, stop, preToolUse, beforeShellExecution). 권한 중계도 여기서 |
| OpenCode | 플러그인 이벤트(session.idle 등) |
| Gemini | 시스템 기본 설정 파일의 훅. 권한 허용은 여전히 안 됨 |
| Crush | 0.99 실행 파일에 PreToolUse, PermissionRequest 흔적이 있음. `-D` 설정 파일의 hooks로 붙는지 |
| Goose, Amp, Grok, Kimi | 실행 한 번에만 붙일 방법이 있는지 다시 본다 |

### B. 서로를 도구로 부르기

- **도구 `delegate`:** mod와 연결 서버가 함께 내준다. 인자는 에이전트, 할 일, 기다릴지 여부다.
- **실행:** 앱이 같은 프로젝트에 그 에이전트의 터미널을 새로 열고 할 일을 입력한다(정할 것 1에서 정함). 맡긴 세션과 맡은 세션은 사이드바에서 이어져 보인다.
- **결과:** 맡은 세션의 턴이 끝나면 A의 턴 끝 사건으로 마지막 답이 맡긴 세션에 돌아간다. 지금 `send_to_session`과 같은 길이다. 그래서 B는 A의 턴 끝 사건이 있는 에이전트부터 된다.
- **권한:** 맡은 세션의 권한 질문은 그 터미널에서 묻는다. 자리를 비웠으면 지금처럼 중계한다.

## 정할 것

1. [x] **맡긴 일을 어디서 돌릴까 (2026-11-06):** 보이는 터미널. 사람이 보고 끼어들 수 있고, 권한 질문도 그 터미널(자리를 비웠으면 휴대폰)에서 받는다. 숨긴 비대화형 실행은 권한 질문을 받을 곳이 없어 쓰지 않는다.
2. **하위 에이전트:** Claude Code처럼 하위 에이전트를 멈추고 이어 가는 기능은 다른 CLI에 그런 입구가 있을 때만 붙인다. 없으면 비운다.

1. [x] **능력 등록과 브리지:** 세션이 등록할 때 `abilities`(turnEnd, cancel, activity, prompt, usage, approvals, subagents)를 알린다. mod는 모두, 연결 서버는 앱이 그 실행에 붙인 것(`--abilities`)을 알린다. 브리지는 턴 끝 답 돌려주기와 취소 명령을 `agent === 'claude'` 대신 이 능력으로 가른다. 능력을 알리지 않던 예전 Claude Code 세션은 mod의 능력을 모두 가진 것으로 본다. Claude Code를 프리셋에 넣는 일은 화면과 엮여 있어 4단계에서 한다.
2. [x] **사건 훅 (Copilot, Qwen, OpenCode):** 권한 훅과 같은 명령이 턴 시작, 도구 시작과 끝, 턴 끝도 연결 서버에 알린다(`HookEvent`, mcp/permission.ts). 연결 서버는 mod처럼 `/sessions/activity`와 `/messages/turn-end`를 보낸다. 세 CLI는 이제 `turnEnd`, `activity` 능력을 알리고, Qwen은 `prompt`도 알려 남은 질문을 프롬프트에 덧붙인다.
   - 턴 끝에는 그 턴에 들어간 메시지 id가 없다. 브리지가 메시지를 세션에 넣은 시각(`outbox.turn_wait`)을 적어 두고, id 없이 온 턴 끝은 턴이 시작되기 전에 들어간 것들에 답한다.
   - Copilot은 permissionRequest 말고는 입력에 사건 이름을 넣지 않아서, 훅 명령의 인자로 넘긴다. 턴 끝의 답은 세션 기록(events.jsonl)에서 마지막 사용자 메시지 뒤의 답을 읽는다. 훅이 답이 쓰이기 전에 불릴 수 있어 몇 번 다시 읽는다.
   - 실제 CLI로 확인: 다른 세션의 질문을 앱처럼 터미널에 넣고 턴을 돌리자, 세 CLI 모두 마지막 답이 질문한 세션에 자동으로 돌아왔다(Copilot과 Qwen은 가짜 모델, OpenCode는 무료 모델).
   - 남은 것: Codex(훅마다 신뢰 기록), Crush(`-D` 폴더의 crush.json hooks), Gemini는 3단계에서 붙인다. Cursor는 턴 단위 훅이 불리지 않아 붙일 수 없다.
3. [x] **Codex, Crush, Gemini의 사건 훅:** 2단계와 같은 방식으로 붙인다.
   - [x] **Codex (2026-11-06):** 권한 훅과 같은 명령을 UserPromptSubmit, PreToolUse, PostToolUse, Stop에도 `-c`로 하나씩 붙인다(사용자의 다른 훅과 hooks.state는 그대로). 중계를 켜면 앱이 다섯 훅 모두를 Codex의 hooks/list로 찾아 신뢰를 기록한다. 하나라도 목록에 없으면 훅을 붙이지 않는다. `turnEnd`, `activity`, `prompt` 능력을 알린다. 남은 질문은 Codex가 developer 메시지로 덧붙인다.
   - [x] **Crush (2026-11-06):** 프로젝트의 crush.json에 훅을 함께 쓴다. Crush의 PermissionRequest는 지켜보기만 해서, 권한 질문은 PreToolUse에서 보낸다. Crush가 묻지 않는 것(읽기 도구, 안전 목록의 명령)은 보내지 않는다. 허용하면 Crush의 질문 없이 실행되고, 거부하면 막힌다. 턴 끝은 TurnEnd, Interrupt, StopFailure 가운데 하나로 온다. `approvals`, `turnEnd`, `activity` 능력을 알린다.
     - 호출 id를 매번 같게 주는 모델이 있어서, 요청 키에 시각을 넣어 앞의 답을 물려받지 않게 했다.
   - 실제 CLI로 확인: Codex 0.166과 Crush 0.99를 임시 HOME, 가짜 모델, 시험용 브리지로 돌렸다. 다른 세션의 질문에 턴 끝 답이 자동으로 돌아갔고, 도구가 도는 동안 working과 열린 도구 수가 보였다. Codex는 남은 질문이 프롬프트에 덧붙었다. Crush는 자리 비움 중 쓰기를 휴대폰 답으로 허용하고 거부했다.
   - [x] **Gemini (2026-11-06):** 0.67은 시스템 기본 설정 파일의 상위 폴더가 모두 root 소유일 때만 그 파일을 읽는다. 그래서 앱이 실행마다 넘기던 파일(연결 서버까지)이 더는 닿지 않는다. 실행 한 번에만 연결 서버를 넘기는 플래그도 없다.
     - 그래서 설정(`geminiExtension`, 기본 꺼짐)을 켜면 앱 폴더의 Switchboard 확장 기능을 `gemini extensions link --consent`로 연결한다. 같은 이름의 다른 확장 기능이 있으면 건드리지 않고, 그 터미널은 예전 방식으로 연다.
     - 확장 기능에는 실행마다 다른 값이 없다. 연결 서버는 `--app-only`로, 터미널 키와 `SWITCHBOARD_EXTENSION=1`이 함께 있는 실행(앱이 확장 기능으로 연 것)에서만 일하고, 그 밖에서는 도구 없는 서버로 답한다. 훅도 같은 표시가 없으면 아무것도 하지 않는다. 설정을 끄고 연결이 남아도 조용하다.
     - 훅은 BeforeAgent(덧붙이기), BeforeTool, AfterTool, AfterAgent(prompt_response)다. 훅은 도구를 허용할 수 없어서 권한 중계는 없다. `turnEnd`, `activity`, `prompt` 능력을 알린다.
     - 확장 기능의 서버에는 `trust`를 줄 수 없어서, 실행마다 `--policy` 파일로 Switchboard 도구만 허용한다(`toolName = "*"`와 `mcpName`. 0.67은 `toolName`이 없는 규칙을 받지 않는다).
     - 실제 CLI로 확인: Gemini 0.67.0을 임시 HOME, 가짜 Gemini API(`GOOGLE_GEMINI_BASE_URL`), 시험용 브리지로 돌렸다. 연결, 네 사건, 턴 끝 답 돌려주기, 남은 질문 덧붙이기, 확인 없는 Switchboard 도구 실행을 확인했다. 앱 밖처럼 연 Gemini에서는 세션이 생기지 않고 도구도 보이지 않았다.
4. [x] **화면:** Claude Code를 프리셋에 넣고, 에이전트별 사용량, 문구, 배지, 지난 세션을 대등하게.

5. [x] **`delegate` (2026-11-06):** 도구 `delegate(agent, task)`를 mod와 연결 서버가 함께 내준다.
   - 브리지가 맡긴 일을 기록하고(`delegations`), 앱에 `delegate-open`을 보낸다. 앱이 열려 있지 않으면 거절해서, 이미 연결된 세션에는 send_to_session으로 묻게 한다.
   - 앱은 맡긴 세션의 폴더에 그 에이전트의 터미널을 새로 연다(Claude Code는 mod로, 다른 CLI는 연결 서버로). 그 터미널 키를 브리지에 알린다(`POST /delegations/:id/opened`, 앱만).
   - 그 키로 등록한 그 에이전트의 세션이 연결되면, 브리지가 맡긴 세션이 보낸 요청으로 할 일을 넣는다. 그래서 턴이 끝나면 지금의 턴 끝 답 돌려주기 길로 결과가 돌아간다. 세션끼리 맡기는 요청 수 제한(8번)에 함께 센다.
   - 터미널이 2분 안에 열리지 않거나, 열린 뒤 5분 안에 세션이 연결되지 않으면, 맡긴 세션에 결과가 오지 않는다고 알린다.
   - 앱이 스스로 연 터미널(예약 프롬프트, 맡긴 일)이 독에 바로 보이게 했다(`term:opened`). 전에는 앱을 다시 띄워야 보였다.
   - 사이드바의 맡은 세션 줄에 "{프로젝트}에서 맡김"을 붙인다.
   - 확인: 브리지 테스트로 흐름 전체와 거절, 실패 알림을 확인했다. 실제 Qwen으로도 돌렸다. 앱이 하는 일(터미널을 열고 키를 알리고, 받은 할 일을 입력)만 스크립트가 대신하고, 맡긴 세션이 Qwen의 답을 그 요청의 답으로 받았다. 앱 창으로 돌리는 확인은 못 했다. 시험용 HOME에서 앱 터미널이 CLI를 찾으려면 셸 설정 파일을 써야 하는데, 에이전트 가드가 막았다.
